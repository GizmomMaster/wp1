# ADR-003. MinIO как файловое хранилище

**Статус:** Принято · 2026-09-04

## Контекст
Поле «Файловое хранилище» в ТЗ не заполнено. Система хранит сканы договоров,
загружаемые реестры, сгенерированные документы, задания на печать, HTML
расчётных листов. Требуется on-prem.

## Решение
MinIO с S3 API. Бакеты разделены по назначению, версионирование, object lock
для сканов договоров, серверное шифрование, доступ только по presigned URL с TTL.

## Следствия
Стандартный S3 API — переход на другое S3-совместимое хранилище не потребует
изменений в коде. Файлы не нагружают Postgres. Появляется отдельный компонент,
требующий резервирования и репликации. Ссылочная целостность «БД ↔ объект»
не транзакционна: нужны фоновая сверка и запрет удаления файла при живых ссылках.

## Альтернативы
Postgres `bytea`/LO — транзакционность и единый бэкап, но раздувание БД и
деградация на больших сканах. Сетевая ФС — привычно для банка, но нет
версионирования и сложнее при нескольких репликах сервиса.
