# ADR-008. Kubernetes on-prem

**Статус:** Принято · 2026-09-04

## Контекст
Банковская система внутри защищённого периметра, облако исключено.
18 сервисов с разным профилем масштабирования, пиковая нагрузка в дни выплат.

## Решение
Kubernetes on-prem. Helm-чарт на сервис, GitOps для конфигурации, HPA для API,
KEDA для воркеров (по длине очереди RabbitMQ), NetworkPolicy с запретом по
умолчанию, sealed secrets/Vault для секретов.

## Следствия
Автоматическое восстановление и масштабирование; воспроизводимость окружений;
изоляция контуров через namespace и сетевые политики. Требует зрелой команды
эксплуатации и отлаженных практик обновления схемы БД (expand/contract).

## Альтернативы
VM + Docker Compose — проще в сопровождении, но ручное масштабирование, что
плохо сочетается с пиковым профилем нагрузки этой системы.
