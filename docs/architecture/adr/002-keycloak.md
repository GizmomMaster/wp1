# ADR-002. Keycloak как поставщик идентичности

**Статус:** Принято · 2026-09-04

## Контекст
Три контура пользователей: сотрудники организаций-клиентов, администраторы банка,
сотрудники банка. Нужны федерация с AD, SSO с ДБО ЮРЛ, MFA, единая политика паролей.

## Решение
Keycloak — единый IdP. Аутентификация, сессии, MFA, федерация с AD, политика
паролей — в Keycloak. Авторизация (матрица «роль → права → область действия») —
в `iam-svc`, поскольку модель ТЗ включает область действия по организациям и
холдингам, чего в стандартных ролях Keycloak нет.

## Следствия
Не пишем собственную аутентификацию — это код, который дорого делать правильно.
Появляется внешняя зависимость: недоступность Keycloak блокирует новые входы
(действующие сессии работают до истечения токена). Требуется отказоустойчивая
конфигурация Keycloak.

## Альтернативы
Собственный Identity на ASP.NET Core Identity — больше контроля, но нужно
самостоятельно реализовывать MFA, федерацию, политики и token exchange.
