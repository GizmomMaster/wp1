# ADR-009. Два BFF: клиентский и административный

**Статус:** Принято · 2026-09-04

## Контекст
Клиентский и административный контуры имеют разные модели доступа, разные
сетевые зоны публикации и разные наборы операций. Прямое обращение SPA к
18 сервисам создало бы связность фронтенда с внутренней декомпозицией.

## Решение
Два BFF-сервиса. Каждый агрегирует вызовы под сценарии своего интерфейса,
хранит refresh-токен в httpOnly cookie (access-токен наружу не отдаётся),
проверяет CSRF, применяет rate limit.

## Следствия
Фронтенд не зависит от нарезки сервисов; изменение декомпозиции не ломает UI.
Административный контур публикуется отдельно и доступен только из внутренней
сети. Появляются два дополнительных сервиса и риск накопления в них бизнес-логики —
BFF выполняет только агрегацию и трансформацию, правила остаются в доменных сервисах.

## Альтернативы
Единый API Gateway для обоих контуров — меньше компонентов, но общая точка
публикации для внутреннего и внешнего трафика, что хуже с точки зрения ИБ.
