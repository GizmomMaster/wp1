# ADR-004. Разделение ролей Kafka и RabbitMQ

**Статус:** Принято · 2026-09-04

## Контекст
Стек включает оба брокера. Без чёткого разделения появляются два способа решать
одну задачу, и выбор становится делом вкуса разработчика.

## Решение
**Kafka** — доменные события: факты о произошедшем, много независимых
потребителей, ретеншн и реплей, порядок в партиции по `organizationId`.
**RabbitMQ** — команды и задачи: адресное поручение одному обработчику,
конкурирующие потребители, DLQ, отложенные повторы, приоритеты.

## Следствия
Аудит, репликация справочников, реакции на изменения статусов — через Kafka с
возможностью переиграть историю. Обработка файлов, генерация документов и вызовы
внешних систем — через RabbitMQ с гарантией однократной обработки и понятным DLQ.
Оба брокера нужно эксплуатировать и резервировать.

## Альтернативы
Только Kafka — потребовала бы реализовать поверх неё семантику рабочих очередей
(DLQ, повторы, приоритеты). Только RabbitMQ — потеря реплея и множественных
независимых потребителей, критичных для аудита.
