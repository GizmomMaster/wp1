# ОРИОН — архитектура и system design

Система начисления денежных средств на зарплатные карты клиентов банка.
Три контура пользователей: административный (сотрудники банка-владельца),
клиентский (сотрудники организаций-клиентов), внутрибанковский (расчётные листы
для собственных сотрудников банка).

## Ключевые архитектурные решения (сводка)

| № | Решение | Кратко |
|---|---|---|
| ADR-001 | Микросервисы | Домены разделены по сервисам, БД на сервис |
| ADR-002 | Keycloak как IdP | OIDC, федерация с AD, бесшовный переход из ДБО ЮРЛ |
| ADR-003 | MinIO (S3 API) | Сканы, реестры, расчётные листы, задания на печать |
| ADR-004 | Kafka + RabbitMQ | Kafka — доменные события и потоки; RabbitMQ — команды воркерам |
| ADR-005 | Собственный workflow-движок | Конфигурируемая статусная модель и маршруты согласования |
| ADR-006 | Transactional Outbox | Гарантия доставки событий без 2PC |
| ADR-007 | Idempotency Key на всех денежных операциях | Защита от двойного начисления |
| ADR-008 | Kubernetes on-prem | Helm, HPA, sealed secrets |
| ADR-009 | Два BFF: client и admin | Разные контуры, разные модели доступа и сетевые зоны |
| ADR-010 | Оркестрация саг в бизнес-сервисах | Без выделенного saga-оркестратора |

## Исходные допущения

Зафиксированы по итогам уточнений с заказчиком:

- **Масштаб**: до ~500 организаций, до 100 тыс. физлиц-сотрудников,
  реестры до 10 тыс. строк, пики в дни выплат (5-е и 20-е числа).
- **Стек**: React (front), .NET 10 (backend), PostgreSQL, Redis, Kafka, RabbitMQ,
  MinIO, синхронное взаимодействие — REST.
- **Развёртывание**: Kubernetes on-prem внутри периметра банка.
- **Аутентификация**: Keycloak.
- **Workflow**: собственный движок на .NET.
- **Из объёма исключён** пункт ТЗ «Модуль замены» (снят заказчиком).

Допущения, принятые архитектором и требующие подтверждения, помечены
в тексте меткой **[ДОПУЩЕНИЕ]** и собраны в [10-roadmap.md](10-roadmap.md).
